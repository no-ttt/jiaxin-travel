# 快取機制說明

說明網站常見的快取做法，以及嘉新旅遊前台目前怎麼做。

---

## 一、伺服器快取 vs 瀏覽器快取

| | 伺服器快取 | 瀏覽器快取 |
|---|---|---|
| 存在哪 | 網站主機上 | 每位訪客自己的瀏覽器 |
| 誰共用 | 所有訪客共用同一份 | 只有這位訪客自己 |
| 解決什麼 | 1 萬人看首頁，不用問後端 1 萬次 | 同一個人在站內逛，不用一直重抓同樣的東西 |
| 怎麼更新 | 計時過期，或後台存檔時通知它清掉（最即時） | 計時過期、特定時機檢查、重新整理 |

常見組合：伺服器快取設「後台存檔就清」，瀏覽器快取設「先用舊的、背後檢查新的」。

> 注意：後端存檔後的通知只會清掉**伺服器**上的快取，已經開著網站的訪客瀏覽器**不會**收到通知。
> 要讓伺服器主動通知瀏覽器，需要另外架即時推播連線（例如 WebSocket），一般形象網站很少這樣做。

---

## 二、瀏覽器快取常見的更新做法

### 1. 什麼時候去檢查

| 做法 | 說明 | 適合 |
|---|---|---|
| 計時過期 | 資料拿到後 N 秒內直接用，過了再抓 | 最基本，大部分網站都有 |
| 事件觸發 | 在特定時機檢查：換頁、切回這個分頁、網路恢復 | 內容型網站最常用 |
| 輪詢 | 每隔固定時間自動問一次 | 股價、訂單狀態等需要即時的資料 |
| 伺服器推播 | 用 WebSocket 等長連線，伺服器有變動就通知瀏覽器 | 聊天、協作文件；形象網站很少用，成本高 |

### 2. 檢查時怎麼更省

| 做法 | 說明 |
|---|---|
| 先顯示舊的、背後抓新的 | 畫面不用等，有變才換上新的（react-query 預設就是這樣） |
| 條件式請求（ETag / 304） | 瀏覽器問「我手上是第 X 版，有變嗎？」，沒變的話後端只回一個很小的「沒變」，不重傳內容。需要後端支援 |
| 版本號 | 後端提供一個很小的 API 只回「目前版本號」，前端比對有變才抓完整內容。需要後端加 API |

## 三、嘉新旅遊目前的做法

### 伺服器端（正式站）

| 層 | 做法 |
|---|---|
| 伺服器快取（Next） | 後端資料抓過一次就存在網站主機上，所有訪客共用。後台存檔時後端會呼叫前台 `/api/revalidate` 清快取；萬一通知漏掉，最多 1 小時也會自動過期 |
| 同一頁內合併 | 產生同一頁時，版面和頁面需要同一份資料就共用，不重複問後端（`src/lib/api/server.ts` 的 `cache()`） |

本機開發（`npm run dev`）不使用伺服器快取，每次都直接問後端，方便看後台改動。

### 瀏覽器端

**1. 全站共用內容（首頁、選單、頁尾、訂購流程）**

| 時機 | 會發生什麼 |
|---|---|
| 打開網站／重新整理 | 伺服器產生頁面時帶最新資料進來，瀏覽器不再另外抓 |
| 站內換頁 | 先用手上的資料立刻顯示，背景向後端問一次，有變就換上新的（`src/app/providers.tsx`） |
| 停在同一頁不動 | 不會更新，等下次換頁或重新整理 |
| 搜尋頁勾篩選、換排序 | 不算換頁，不檢查 |

**2. 各頁自己的主要內容（行程詳情、旅客須知、簽證、主題集合頁等）**

- 由伺服器產生，每次站內進到這一頁都會向伺服器拿新的一份。伺服器有「後台存檔就清快取」，所以是最新的。
- 按瀏覽器「上一頁／下一頁」時，直接顯示剛才看過的畫面，不重抓。

**3. 瀏覽器自己查詢的資料（搜尋結果、保證出團、主題集合頁「查看更多」）**

- 同樣的條件在 30～60 秒內再查，直接用上次結果。
- 超過時間再查同樣條件，先顯示上次結果，背景重抓，有變就換上新的。
- 換了條件（例如換篩選）一定重新查。

### 目前有／沒有的機制

| 項目 | 狀態 |
|---|---|
| 先顯示舊的、背後抓新的 | ✅ 有 |
| 換頁時檢查 | ✅ 有 |
| 後台自己存檔後，同一個瀏覽器馬上更新 | ✅ 有 |
| 切回分頁時檢查 | ❌ 沒有（可加，只需改前端） |
| ETag / 304 | ❌ 沒有（需後端支援，目前資料量小，效益不大） |
| 推播 | ❌ 沒有（形象網站不需要） |

## 四、業主在後台存檔後，訪客多久看到

| 訪客狀態 | 看到新內容的時機 |
|---|---|
| 新打開網站 | 馬上 |
| 已開著、重新整理 | 馬上 |
| 已開著、站內換頁 | 換頁那一刻 ※ |
| 已開著、一直停在同一頁 | 要等他換頁或重新整理 |

※ 換頁檢查走的是後端公開 API，後端對它設了「CDN 可快取 60 秒」（`Cache-Control: public, s-maxage=60, stale-while-revalidate=300`）。
如果 Cloudflare 有照這個設定快取 `/api/v1/public/*`，換頁時可能拿到稍舊的內容：一般慢 1 分鐘內，`stale-while-revalidate=300` 的情況下最多可能慢到幾分鐘。重新整理不受影響。是否有快取需向後端確認。
